# PC 管理端登录与鉴权联调（v4）

> 适用：PC 后台（Vue / React）前端开发与 AI 编码代理。
> 服务端契约权威来源：`server/swagger.json`（Swagger 2.0）。
> 本文只讲 **PC 登录 / 角色选择 / 权限 / 数据范围 / 会话恢复**；业务接口见 `API_INDEX.md` 与 `AGENTS.md`。

## 1. 环境与统一响应

| 项 | 值 |
|---|---|
| 接口地址（端口） | `http://115.159.151.158:8081/api/v1` |
| 接口地址（域名） | `http://followup.ijunyuan.cn/api/v1` |
| WebSocket | `ws://115.159.151.158:8081/api/v1/ws?token=<accessToken>` |
| Swagger UI（dev） | `http://115.159.151.158:8081/api/v1/swagger-ui.html` |
| 服务器 | `tcpkg:/home/wyc/followup`，`start.sh` 启停，dev profile |

**HTTP 状态恒为 200**，一切语义看响应体：

```json
{ "code": 0, "message": "ok", "data": {} }
```

| code | 含义 | 前端处理 |
|---|---|---|
| 0 | 成功 | 取 `data` |
| 400 | 业务错误（密码错、参数错、登录票据过期、账号无 PC 角色等） | 弹 `message`，**不跳登录** |
| 401 | access token 缺失/过期/非法 | 用 refreshToken 静默刷新并重试一次 |
| 402 | refreshToken 无效/过期 | 清凭证 → 跳登录页 |
| 403 | 无权限 | 提示无权限，不跳登录 |
| 500 | 服务端异常 | 通用错误提示 |

分页统一：`data = { list: [], total, page, pageSize }`。  
鉴权头：`Authorization: Bearer <accessToken>`（公开接口除外）。

## 2. 登录方式总览

| 角色 | 登录方式 | 接口 |
|---|---|---|
| **PC 管理端**（公司管理/医院管理/科室管理/客服/驻点/看板） | **账号密码 → 角色列表 → 选角色换 token** | `/auth/pc/login`、`/auth/pc/select-role`、`/auth/pc/switch-role` |
| 小程序客服/陪诊师 | 账号密码 | `/auth/login`（兼容，PC 新前端不用） |
| 小程序医生 | 手机号 + 验证码，首次按医生库手机号自动建号 | `/auth/doctor/sms-login` |
| 小程序患者 | 微信 / 短信 / 账密 | `/auth/wx-login`、`/auth/sms-login`、`/auth/register`、`/auth/login` |

> PC 登录页**只收集账号密码**；角色选择是登录后的第二步。不要再用旧文档里的“登录页选角色”。

## 3. 两步式登录（PC 必须用这条）

### Step 1：账密校验 → 登录票据 + 角色列表

```
POST {base}/auth/pc/login
Content-Type: application/json

{ "username": "multi", "password": "1" }
```

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "loginTicket": "eyJhbGciOiJIUzUxMiJ9...（5 分钟有效，只能用于 select-role）",
    "user": { "id": 910009, "name": "多角色账号", "username": "multi", "avatar": null },
    "roles": [
      { "code": "pc_admin", "name": "电脑端管理员", "terminal": "PC", "baseRole": "ADMIN", "dataScope": "ALL" },
      { "code": "pc_customer_service", "name": "电脑端客服", "terminal": "PC", "baseRole": "CS", "dataScope": "SELF" }
    ],
    "autoSelectRoleCode": null
  }
}
```

- `roles` 只返回 `terminal=PC/ALL` 且启用的角色。
- 只有 1 个角色时 `autoSelectRoleCode` 有值，前端可直接自动进入 Step 2。
- 账号停用/无启用角色 → 400；密码错 → 400“用户名或密码错误”。
- **`loginTicket` 不要持久化**；5 分钟过期或选角色失败时退回 Step 1。

### Step 2：选角色 → accessToken + refreshToken

```
POST {base}/auth/pc/select-role
Content-Type: application/json

{ "loginTicket": "eyJ...", "roleCode": "pc_admin" }
```

```json
{
  "code": 0,
  "data": {
    "token": "eyJ...（access，2 小时）",
    "refreshToken": "eyJ...（refresh，7 天，Redis 白名单）",
    "user": {
      "userId": 910009,
      "username": "multi",
      "name": "多角色账号",
      "role": "ADMIN",
      "roleCode": "pc_admin",
      "roleName": "电脑端管理员",
      "terminal": "PC",
      "permissions": ["menu:dashboard", "dashboard:view", "menu:users", "patient:view", "..."],
      "dataScope": "ALL",
      "hospitalId": null,
      "departmentId": null,
      "deptScope": null,
      "doctorDictId": null
    },
    "roles": [
      { "code": "pc_admin", "name": "电脑端管理员", "terminal": "PC", "baseRole": "ADMIN", "dataScope": "ALL" },
      { "code": "pc_customer_service", "name": "电脑端客服", "terminal": "PC", "baseRole": "CS", "dataScope": "SELF" }
    ]
  }
}
```

前端必须使用返回的 `user.permissions[]` 渲染菜单/按钮：

```ts
const can = (code: string) => user.permissions.includes(code)

// 菜单：menu:*
{ can('menu:dashboard') && <MenuItem to="/dashboard">数据看板</MenuItem> }
{ can('menu:users') && <MenuItem to="/patients">用户管理仓</MenuItem> }

// 按钮：动作码
<Button disabled={!can('patient:create')}>新增患者</Button>
```

> 权限码全集见 `GET /permissions/tree`（分组 → 页面 → 动作），或仓库 spec 附录 A。
> 不要用 `role === 'ADMIN'` 硬编码菜单；`role` 是基础枚举，`roleCode` 才是动态角色。

### Step 3（可选）：已登录切换角色

```
POST {base}/auth/pc/switch-role
Authorization: Bearer <accessToken>
Content-Type: application/json

{ "roleCode": "pc_customer_service" }
```

- 返回结构与 Step 2 相同（新 token/refreshToken）。
- 切换后**清空页面缓存、重新拉菜单和首屏数据**；权限与数据范围都变了。
- 旧 refreshToken 仍保留可用（多设备/多角色切换不互相踢）。

### 恢复会话

```
GET {base}/auth/me
Authorization: Bearer <accessToken>
```

返回当前 `roleCode/roleName/terminal/permissions[]/roles[]` 与数据范围。刷新页面时用它重建菜单，**不要重新登录**。

```json
{
  "code": 0,
  "data": {
    "userId": 910009,
    "username": "multi",
    "role": "ADMIN",
    "roleCode": "pc_admin",
    "roleName": "电脑端管理员",
    "terminal": "PC",
    "permissions": ["menu:dashboard", "..."],
    "dataScope": "ALL",
    "hospitalId": null,
    "departmentId": null,
    "deptScope": null,
    "roles": [ ... ]
  }
}
```

## 4. 刷新与登出

```
POST {base}/auth/refresh?refreshToken=xxx
  → { token, refreshToken, user, roles }      // 旧的 refresh 用一次即失效

POST {base}/auth/logout?refreshToken=xxx
Authorization: Bearer <accessToken>
  → 注销本设备 refresh token（多设备不互相影响）
```

- access token 2 小时；refresh token 7 天，服务端 Redis Set 白名单。
- 401 时静默刷新并重试一次；不要无限重试。
- 刷新失败（402）清本地凭证并跳登录。

## 5. 数据范围（服务端强制）

| dataScope | 含义 | 前端展示 |
|---|---|---|
| `ALL` | 全量 | 可显示医院筛选（ADMIN/DASHBOARD） |
| `HOSPITAL` | 本院 | 隐藏医院筛选；可显示科室筛选 |
| `DEPARTMENT` | 本科室 | 隐藏医院/科室筛选（由 token 固定） |
| `STATION` | 驻点授权医院/科室 | 医生录入只能选 `scopeJson.hospitalIds/departmentIds` |
| `SELF` | 本人/匹配关系 | 患者列表按客服匹配关系/陪诊订单关系 |
| `CUSTOM` | 自定义（scopeJson） | 按角色配置 |

- `GET /auth/me` 返回 `hospitalId/departmentId/deptScope/scopeJson`；其中 `DEPT_ADMIN` 映射为 `role=HOSPITAL_ADMIN + deptScope=DEPT`。
- 患者列表、看板、医生录入等服务端会再次校验；**前端传越权 ID 不会生效**。
- 不要在前端做“数据隔离”的安全承诺；前端只负责隐藏无权限入口。

## 6. 动态 RBAC 要点

- 角色表 `sys_role`、权限表 `sys_permission`、角色权限 `sys_role_permission`、用户角色 `sys_user_role`。
- 一人多角色；登录时按所选角色签发 JWT，JWT 携带 `roleCode/permissions/dataScope/scopeJson` 等 claim。
- 新 PC 接口用 `hasAuthority('权限码')`；旧接口仍按 `hasRole` 基础枚举放行。
- **取舍**：取消自定义角色的某项权限，只影响新 PC 接口与前端菜单/按钮，旧接口仍按 baseRole 放行。
- 角色权限修改在下一次签发 token 时生效；已签发 token 最长 2 小时仍带旧权限。
- 系统内置角色（`system=1`）不可删除、不可改 `code/baseRole`；有关联账号的角色删除会 400。

## 9. 前端实现建议

```ts
// 登录状态（示例）
type LoginState = {
  token: string
  refreshToken: string
  user: {
    userId: string | number
    username: string
    name?: string
    role: string
    roleCode: string
    roleName: string
    terminal: string
    permissions: string[]
    dataScope: string
    hospitalId?: string | number | null
    departmentId?: string | number | null
    deptScope?: string | null
    doctorDictId?: string | number | null
  }
  roles: RoleView[]
}

// 角色选择页只展示 login 返回的 roles[]
// 选中后调用 select-role，保存 token/refreshToken/user/roles
// 刷新页面：GET /auth/me → 用返回的 user 重建菜单；失败再跳登录
```

- `loginTicket` 放内存/sessionStorage，不写 localStorage 长期保存。
- token 存储遵循项目安全策略；无论存哪里，都要在请求拦截器统一注入。
- 切换角色后重新拉取菜单与首屏；不要保留旧角色的页面缓存。
- 权限判断只读 `permissions[]`；不要发探测请求判断按钮权限。

## 10. 常见坑

1. **`loginTicket` 过期**：5 分钟；过期返回 400“登录票据无效或已过期”，退回账号密码页。
2. **医生账号 PC 登录 400**：医生只有 `mobile_doctor`，没有 PC 角色；不要给医生生成 PC 后台入口。
3. **`role` vs `roleCode`**：`role` 是基础枚举（ADMIN/HOSPITAL_ADMIN/...），`roleCode` 是动态角色（pc_admin/...）；菜单用 `permissions[]`，不要用 `role`。
4. **DEPT_ADMIN 映射**：JWT 里 `role=HOSPITAL_ADMIN`、`deptScope=DEPT`；不要在前端判断 `role === 'DEPT_ADMIN'`。
5. **权限变更延迟**：角色权限改完要重新登录/切角色才生效；已登录用户最长 2 小时内还是旧权限。
6. **刷新 token 旋转**：refresh 成功会换新 refresh，旧的立即失效；并发刷新要加锁，避免互相踢。
7. **多设备登录**：允许，互不剔除；登出只注销当前设备的 refresh。
8. **雪花 ID**：19 位，JS `JSON.parse` 会丢精度；用 `json-bigint` 或按字符串处理。
9. **HTTP 恒 200**：不要用 `fetch` 的 `res.ok`/axios 的 status 判断业务成功，必须看 `code`。
10. **401 重试一次**：刷新成功后重试原请求；刷新也失败则 402 清凭证跳登录，避免死循环。
