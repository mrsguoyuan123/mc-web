# 指令 R1：角色管理列表页（RoleManage.vue）

> 模块定位：与「用户管理仓」平级的系统权限管理模块，管理角色基础信息、功能权限、数据范围与关联账号。
> **接口口径：rbac 模块（动态角色与权限）13 个端点已 swagger 定稿；本列表对接 `GET /roles`，其余抽屉/增改停删在 R2 指令落地。**
> 空值口径：字段缺失（null/undefined/空串）显示红色「接口未提供」，0 值正常显示；缺失判定复用 `../utils.js` 的 `isMissing` / `MISSING_TEXT`。

## 一、技术规范（强制）

- Vue3 `<script setup>` 组合式 API + Element Plus，**不要 TypeScript**。
- 接口从 `../../api/index.js`（按组件实际层级调整）导入；api 层按 rbac swagger 导出同名函数，组件直接调用。
- 接口未就绪/无数据：列表与抽屉显示空态占位，不画假角色、假权限数。
- 日期时间 `YYYY-MM-DD HH:mm`；表格 `table-layout: fixed`。
- 雪花 ID 已由封装层转字符串，路径/入参 id 一律按字符串传递。

## 二、页面入口与组件

`src/views/roleManagement/index.vue`

### 页面标题区
- 主标题「角色管理」，副标题「管理角色权限、数据范围和关联账号。」
- 右上角主按钮「+ 新增角色」。

### 筛选区
- 搜索框：占位「搜索角色名称或角色编码」，入参 `keyword`，按名称/编码模糊查询。
- 下拉「全部适用端」：`PC` 电脑端 / `MOBILE` 手机端 / `ALL` 全部；入参 `terminal`。
- 下拉「全部状态」：启用（1）/ 停用（0）/ 全部；入参 `status`。
- 「重置」按钮：清空筛选条件并重新拉取列表。

## 三、角色列表表格

表格列：角色名称、角色编码、适用端、数据范围、权限数量、关联账号、状态、更新时间、操作。

### 列表项字段映射（`SysRole`，swagger 定稿）

| 列 | 接口字段 | 展示规则 |
|---|---|---|
| 角色名称 | `name` | `system=1` 旁挂「系统内置」深色标签；`baseRole=DASHBOARD` 挂「仅看板」黄标签 |
| 角色编码 | `code` | 灰底小标签样式，如 `pc_admin` |
| 适用端 | `terminal` | `PC` 电脑端（蓝标签）/ `MOBILE` 手机端（紫标签）/ `ALL` 全部（灰标签） |
| 数据范围 | `dataScope` | `ALL` 全部数据 / `HOSPITAL` 本院数据 / `DEPARTMENT` 本科室 / `STATION` 驻点数据 / `SELF` 本人·指定客户 / `CUSTOM` 自定义范围 |
| 权限数量 | （前端由权限码长度估算，或后端补充） | 整数；接口未返回时该列显示红色「接口未提供」，不臆造 |
| 关联账号 | `accountCount`（若后端未在列表返回，点列跳转抽屉「关联员工」页签取数） | 整数；缺失显示红色「接口未提供」 |
| 状态 | `status` | 1 启用（绿点）/ 0 停用（灰点） |
| 更新时间 | `updateTime` | `YYYY-MM-DD HH:mm` |
| 操作 | — | 见下 |

### 操作列（按行状态/内置标记差异化显示）
- **编辑**：铅笔图标，打开编辑角色抽屉（R2，编辑态）。
- **权限配置**：权限图标，直接打开抽屉并定位「功能权限」页签。
- **复制**：复制角色，以当前角色为模板新建（抽屉复制态，R2）。
- **停用 / 启用**：文案随 `status` 切换；停用弹确认框（见第五节），调 `PUT /roles/{id}/status`。
- **删除**：红色垃圾桶；**存在关联账号时置灰不可删**，悬停提示「存在关联账号」；系统内置角色按后端规则隐藏/置灰；可删时弹确认框（见第五节），调 `DELETE /roles/{id}`。

### 列表数据口径
- 分页参数：`page`（默认 1）、`pageSize`（默认 20，上限 100）；返回 `{ list, total, page, pageSize }`。
- 空列表显示「当前无角色」空态。
- 角色变更（保存/停用/删除）后刷新列表。

## 四、筛选与交互规则

- 搜索输入防抖；切换下拉即时刷新。
- 重置：清空关键词、适用端、状态，回到默认列表。
- 操作二次确认：停用、删除必须走确认弹窗，不直接执行。
- 权限变更保存后即时生效（列表副标题注明「权限变更保存后即时生效」）。

## 五、确认弹窗

### 5.1 确认停用角色
- 标题「确认停用角色」。
- 文案：停用「{name}」后，关联的 {关联账号数} 个账号将失去该角色权限。确认继续吗？
- 按钮：「取消」「确认停用」（红色）。
- 确认后调 `updateRoleStatusById(id, 0)`，成功刷新列表；失败给提示。
- 重新启用调 `updateRoleStatusById(id, 1)`。

### 5.2 删除角色
- 标题「删除角色」。
- 文案：删除「{name}」后将无法恢复，相关权限配置也会一并移除。确定删除该角色吗？
- 按钮：「取消」「确认删除」（红色）。
- 仅无关联账号、非内置锁定角色可触发；确认后调 `deleteRoleById(id)`；后端对内置/有关联账号角色返回 code=400，前端按提示兜底。

## 六、接口对接（rbac 定稿）

### 本列表使用
- `GET /roles` → `getRolePage(params)`：入参 `keyword / terminal / status / page / pageSize`；返回 `PageResult<SysRole>`。

### 抽屉/操作将在 R2 对接
- `GET /roles/{id}` 详情、`POST /roles` 新增、`PUT /roles/{id}` 编辑、`POST /roles/{id}/copy` 复制。
- `GET/PUT /roles/{id}/permissions`、`GET /permissions/tree` 权限树。
- `GET/PUT /roles/{id}/data-scope` 数据范围。
- `GET /roles/{id}/accounts` 关联账号。

### 待联调确认项
- 列表是否直接返回 `permissionCount` / `accountCount`；未返回时权限数量前端按已授权限码长度估算。
- 内置角色清单与前端锁定规则（`system=1` 是否一律禁删、编码只读）。
- `baseRole` 基础架构角色枚举：`ADMIN / HOSPITAL_ADMIN / DEPT_ADMIN / CS / CAREGIVER / DOCTOR / DASHBOARD`，下拉字典来源。

## 七、api 层函数约定（api/index.js）

按 rbac swagger 导出，组件统一从这里导入：

```js
// 角色分页列表（R1 使用）
export function getRolePage(params = {}) {
  return http.get('/roles', params)
}
// 其余 R2 使用：createRole / getRoleById / updateRoleById / deleteRoleById /
// copyRoleById / updateRoleStatusById / getRolePermissionsById /
// updateRolePermissionsById / getPermissionTree / getRoleDataScopeById /
// updateRoleDataScopeById / getRoleAccountsById（路径与入参以 rbac swagger 为准）
```
