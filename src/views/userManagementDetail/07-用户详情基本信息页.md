# 指令 7/6：用户详情页 · 基本信息 Tab（只读 + 编辑 + 附件识别弹窗）

> 前置：指令 1 列表操作列「查看详情」、指令 4 展开行「查看详情」已抛出 `view-detail`，本指令落地为独立详情页/详情视图。
> 交付形态：本指令只描述需求与结构，由 Codex 在现有工程内生成组件；**对接已有患者详情接口**，接口未就绪处用空态 + 加载占位，不在前端写死示例条目。

## 一、技术规范（强制）

- Vue3 `<script setup>` 组合式 API + Element Plus，**不要 TypeScript**。
- 工程内复用：`../utils.js` 的 `displayText / formatTime / formatDate`；接口从 `../../../api/index.js` 导入（按组件实际层级调整）。
- 日期 `YYYY-MM-DD`、时间 `HH:mm`；表格/栅格 `table-layout:fixed`；雪花 ID 已由封装层转字符串。
- 所有展示值来自接口；字段缺失显示 `接口未提供`，红色，不写死张三那组 Mock 业务数据。图中字段值仅作为「标签/布局参照」，不作为前端常量。
- 其余 Tab（附件管理、饮食分析、运动分析、体重动态、血糖血压、用药提醒、睡眠管理、检查报告）本指令只留 Tab 壳与切换，内容后续指令补齐。

### 5.2 医疗信息

#### 既往病史（12 个是/否标签，4 列网格）
高血压、心脏病、糖尿病、脑血管疾病、呼吸系统疾病、肾脏疾病、肝脏疾病、手术外伤史、输血史、药物/食物中毒史、传染病史、病毒性肝炎。

- 每个标签为一个可选中条目：选中（是）= 暖色描边 + 右侧橙色「是」徽标；未选（否）= 灰底 + 灰色「否」徽标。

## 六、上传附件并识别弹窗

- 入口：基本信息 Tab 右上角「上传附件并识别」。
- 弹窗标题「上传附件并识别」，副标题「上传用户档案、病历或表格，系统将自动识别并填充基本信息字段。」
- 上传区：虚线框拖拽区，居中上传图标；文案「点击选择文件，或拖拽至此处」；副文案「支持 PDF、JPG、PNG、DOCX，最大 20MB」。
- 校验：
  - 格式白名单 `pdf/jpg/jpeg/png/docx`，不符提示「仅支持 PDF、JPG、PNG、DOCX」。
  - 大小 ≤ 20MB，超限提示「文件不能超过 20MB」。
  - 支持单选/多选（按后端能力，先单选占位）。
- 底部按钮：「取消」（关闭弹窗）、「开始识别」（主按钮；未选文件时置灰）。
- 交互：选择文件后显示文件名/大小清单；点「开始识别」调识别接口，按钮 loading；识别成功后回填对应基本信息字段并关闭弹窗（或保留弹窗显示识别结果，以后端流程为准）；识别失败弹出错误提示，不清空已选文件。
- 接口：附件上传 + 识别（路径待后端补，见第七节）；未就绪时点击「开始识别」给空态/待联调提示，不伪造识别结果。

### 字段映射原则（以后端 swagger 为准，前端做兜底）

- 列表行已有字段：`name/gender/age/region/phone/heightCm/weightKg/idCard/matchedCsName/matchedCaregiverName/doctorName/insuranceId/departmentName/hospitalName`。

## 八、编辑态逻辑

- 点「编辑信息」→ 各分区控件由只读文本切换为输入框/下拉/日期选择/文本域；顶部按钮变为「取消」「保存修改」。
- 「取消」→ 放弃本次改动，用接口原始数据重置，回到只读态。
- 「保存修改」→ 校验必填（姓名、性别、出生日期、身份证号等，以后端必填规则为准）→ 调 `updatePatientDetail`；成功提示并刷新详情，失败保留表单并展示错误。
- 编辑过程中切换 Tab 需提示「有未保存修改」（确认后离开/留存，按常规表单确认交互）。
