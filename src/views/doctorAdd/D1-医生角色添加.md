# D1 · 医生角色添加（驻点协助注册）

> 通用约定：Vue3 `<script setup>` + Element Plus，不用 TypeScript；雪花 ID 一律字符串；缺失值显示红色「接口未提供」（`MISSING_TEXT`，`#f56c6c`）；`isMissing` 只认 `null/undefined/''`；工具从 `@/utils/index.js` 导入。

## 1. 文件

| 文件 | 职责 |
| --- | --- |
| `src/views/doctorAdd/index.vue` | 页面主文件：标题 + 提示条 + 表单 + 右侧说明 + 最近录入表格 |
| `src/api/modules/doctor.js` | 已存在，直接复用；本页只补 3 个占位函数（见第 6 节） |

接口从 `../../api/index.js` 导入（`doctor.js` 的函数已由 `src/api/index.js` 重导出）。页面所在目录以你项目实际为准，这里默认 `doctorAdd`。

## 3. 页面头部

- 标题 `医生角色添加`；副标题 `驻点可协助管理员注册医生角色。录入方式与管理员端"新建医生"一致，提交后直接进入医生管理仓。`
- 提示条（浅蓝底 + info 图标）：标题 `驻点协助注册通道`，正文 `本入口只负责创建医生基础角色，不包含医生执照或资质附件，也不进入审核队列。管理员可在医生管理仓继续维护团队关系、状态和负责用户。`

## 4. 表单字段

| 字段 | 控件 | 校验 |
| --- | --- | --- |
| 医生姓名 `*` | input，placeholder `例如：周医生` | 必填，2–20 字，去首尾空格 |
| 职称 `*` | select | 必填，选项见 D-G1 |
| 专科 `*` | select，placeholder `请选择专科` | 必填 |
| 手机号 `*` | input，placeholder `请输入 11 位手机号` | 必填，`/^1[3-9]\d{9}$/` |
| 区域 `*` | select，placeholder `请选择区域` | 必填 |
| 医院 `*` | select，placeholder `请选择医院` | 必填；**未选区域时 disabled**，区域变更时清空已选医院 |
| 科室 `*` | select，placeholder `请选择科室` | 必填；区域/医院变更时清空 |
| 上级医生 | select，默认 `暂不指定` | 可空，`clearable` |

表单下方「提交后信息」只读卡：`医生状态 在职`、`注册渠道 驻点协助`、`管理员同步 立即同步`。全部为前端固定文案，不传后端、不读接口。

底部按钮：`重置`（清空全部字段回到初始态，含联动下拉）与 `确认添加医生角色`（主按钮）；提交中 loading 且禁用，防重复点击。

## 5. 最近录入的医生

表头：`医生` / `职称·专科` / `医院·科室` / `手机号` / `状态` / `注册渠道`，首列显示序号。

- 姓名列：`doctorName`；职称与专科上下两行，职称黑色、专科灰色小字
- 医院与科室同样上下两行
- 状态列：绿底标签，取 `status` 文案（在职/离职），未知值灰标 + 原文
- 注册渠道列：`STATION_ASSIST` → 橙标「驻点协助」，`ADMIN` → 蓝标「管理员」，未知值灰标 + 原文
- 默认取前 6 条，按 `createTime` 倒序；无数据显示「暂无录入记录」

## 6. 缺口（必须按此处理）

| 编号 | 缺口 | 处理 |
| --- | --- | --- |
| D-G1 | 无职称字典接口（dict 模块只有区域/科室/医生/标签） | 在 `doctor.js` 加占位 `getDictTitleList` 并注释 `pending`；下拉先用本地常量 `['住院医师','主诊医师','主治医师','副主任医师','主任医师']`，加注释「待后端字典接口替换」，**不得编造 URL** |
| D-G2 | 无医院列表接口（`hospital.js` 只有患者视角 3 个，dict 无医院） | 加占位 `getDictHospitalList`；未接通前医院下拉 disabled + tooltip「医院字典接口待补」，不要用患者数据冒充医院列表 |
| D-G3 | 区域 → 医院 → 科室 的级联关系未知 | 按 `areaId` / `hospitalId` 逐级传参尝试；无返回则只做「清空下级」不做本地过滤，三级联动失败不阻塞表单填写 |
| D-G4 | `createDoctor` 是否接收 `registerChannel` / `stationId` 未知 | 提交体不主动塞这两个字段（若后端由 token 推导）；返回后表格渠道列若为 `null`，显示「接口未提供」，并在缺口清单反馈 |
| D-G5 | `getDoctorPage` 是否支持 `stationId` / `registerChannel` / `createdBy` 过滤、按 `createTime` 排序未知 | 传 `{ stationId, registerChannel: 'STATION_ASSIST', page: 1, pageSize: 6, sort: 'createTime,desc' }`；若后端忽略导致返回全平台数据，表头加小字「当前为全量最近录入」，**禁止前端本地按条件过滤后再展示** |
| D-G6 | `getDoctorOptions` 是否支持按 `departmentId` 过滤未知 | 传参尝试；不支持则下拉展示全量医生并可搜索 |
| D-G7 | 「注册责任留痕」的当前驻点名 | 取 `getCaregiverScope`；缺失时该行显示「接口未提供」，其余两行（所属驻点、数据范围）为静态文案 |

## 7. 交互

- 提交成功后：`ElMessage.success('医生角色添加成功')`，清空表单，刷新最近录入表格
- 提交失败：保留表单内容，提示后端返回的 message；不自动重试
- `重置` 用 `formRef.resetFields()` 后再手动清空级联下拉的选中项
- 「最近录入」不随表单变化自动刷新，只在提交成功后刷新
- 页面无编辑、删除、查看详情入口，不要自行添加

## 8. 验收

1. 八个字段齐全，四个带 `*` 的必填项为空时按钮触发校验并给出字段级红色提示
2. 手机号非 11 位或非 1 开头时拦截
3. 未选区域时医院禁用；改区域会清空医院与科室
4. 「提交后信息」三行文案与设计稿一致，且不随表单值变化
5. 提交成功后再查表格，新医生出现在第一行，注册渠道显示「驻点协助」
6. 医院/职称接口未接通时，下拉禁用且有 tooltip，不出现空白可点的下拉
