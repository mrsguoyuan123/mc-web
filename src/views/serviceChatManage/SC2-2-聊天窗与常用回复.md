# 指令 SC2-2：中部聊天窗与常用回复 FAQ

> 模块定位：工作台中部沟通区：消息气泡流 + 输入框 + 常用回复；含历史记录弹窗与放大聊天窗。
> **接口口径：会话消息列表/发送/已读复用 conversation 模块（出口已导出）；FAQ 对接 `/cs/faq`。**
> 前置：当前选中患者 `currentPatientId` 由 SC1 `index.vue` 传入；AI 建议问题可来自 SC2-1 预判卡。
> 注意：conversation 以「会话 id（conversationId）」为路径主键，患者 id 与会话 id 的映射方式见第三节「待联调」。

## 一、技术规范（强制）

- Vue3 `<script setup>` + Element Plus，**不要 TypeScript**；接口从 `../../api/index.js`（出口统一重导出，本项目无 `@` 别名），工具从 `@/utils/index.js`。
- 消息时间 `YYYY-MM-DD HH:mm`；消息发送人/类型枚举复用全局 `SENDER_TYPE_TEXT` / `MESSAGE_TYPE_TEXT`。
- 切换患者清空消息流与输入框；各区块独立容错。

## 二、组件

```
src/views/serviceChatManage/components/
├── CsChatPanel.vue        # 中部：消息流 + 输入框 + 常用回复/FAQ
├── CsMessageList.vue      # 消息气泡列表（聊天窗/历史弹窗/放大窗复用）
└── CsFaqPanel.vue         # 常用回复面板（FAQ 检索 + 填入输入框）
```

## 三、会话消息流（复用 conversation 模块）

### 3.1 会话定位

- 进入选中患者后，先取该患者所属会话：
  - 优先 `getConversationWorkspaceById(conversationId)`（工作台会话上下文）；
  - 或用 `getMyConversations()` / `getConversationPage(params)` 按患者匹配出当前会话，拿到 `conversationId` 与会话元信息（对方、未读数、最后消息、优先级/状态）。
- **待联调**：患者 `patientId` 如何映射到 `conversationId`（会话对象是否回传 `patientId`，或需按患者唯一查询会话）；在映射口径确认前，组件预留 `conversationId` 状态，取不到时消息流显示空态「暂无进行中的会话」，不伪造气泡。

### 3.2 消息列表：`getConversationMessagesById(conversationId, params)`

- 路径主键为 `conversationId`（字符串）；`params` 含分页 `page/pageSize`，消息按时间倒序/正序展示（按工程既有分组规则，历史在前）。
- 消息项按会话既有结构渲染：发送人、发送人类型、内容、消息类型（文本/图片/附件/通话卡片）、时间、已读状态。
- 字段真实子名以 conversation 模块封装注释为准；未确认字段按空值口径兜底，不臆造。

### 3.3 发送消息：`sendConversationMessageById(conversationId, payload)`

- 客服在工作台发送走 `sendConversationMessageById`；`payload` 含文本内容、消息类型、附件引用（附件本体先经 `uploadFile` 上传拿 url）。
- 发送成功后把新消息追加进消息流并刷新未读；失败保留输入内容并提示，不清空。
- 患者端侧发送对应 `sendMyConversationMessageById`，客服工作台不调用。

### 3.4 已读与会话状态

- 打开会话/消息滚动到底部后，调 `markConversationReadById(conversationId)` 标记已读，刷新未读计数。
- 会话优先级/状态如需客服操作，用 `updateConversationPriorityById` / `updateConversationStatusById`；本工作台默认只读会话状态，不主动改优先级。
- 其他 conversation 能力（回复模板、转人工、会话评价、消息编辑/审核）按需对接，不在本窗默认启用。

### 3.5 气泡与交互

- 气泡布局：患者/AI 居左，客服居右；头像、姓名、时间戳；消息类型样式预留。
- `getCsPatientById` 返回的 `timeline` 只是 MESSAGE/CALL 混合摘要，不等同消息流；如需侧边摘要可单独分区展示，不与 conversation 消息混用。

## 四、历史记录弹窗 / 放大聊天

- 「历史」弹窗与「放大」全屏弹窗均为同一消息流的展示形态，复用 `CsMessageList.vue` 与第三节消息数据；不新增独立接口。
- 弹窗内保留输入框与发送按钮，发送走 `sendConversationMessageById`；无可用会话时按钮置空态提示。
- 放大窗全屏覆盖，关闭后回到工作台主视图；历史弹窗标题为患者编号/姓名。

## 五、常用回复 / FAQ（`CsFaqPanel.vue`）

### 数据：`getCsFaq(params)` → `GET /cs/faq`

入参：
- `keyword`：问题模糊关键字，检索框输入防抖。
- `surgeryType`：术式，取当前患者 `surgeryType`；不传时返回通用问答（待联调确认）。

返回 KbEntry 数组，元素 `{ id, question, answer, category, department, similarQuestionsJson, surgeryType, tagsJson, publishStatus, status, hitCount }`：
- 列表展示 `question`；选中后正文展示 `answer`；`category / department` 作次要标签。
- `similarQuestionsJson`、`tagsJson` 用 `safeParseJson` 解析；解析失败按空。
- 常用回复一键填入聊天输入框（仅填文本，发送仍走 `sendConversationMessageById`）。
- 仅展示启用中条目；`publishStatus / status` 过滤口径待联调确认。

## 六、本段接口对接

| 用途 | 函数 | 模块 / 路径（以封装注释为准） |
|---|---|---|
| 会话上下文 | `getConversationWorkspaceById(conversationId)` | conversation |
| 会话列表/按患者匹配 | `getMyConversations()` / `getConversationPage(params)` | conversation |
| 消息列表 | `getConversationMessagesById(conversationId, params)` | conversation |
| 发送消息 | `sendConversationMessageById(conversationId, payload)` | conversation |
| 标记已读 | `markConversationReadById(conversationId)` | conversation |
| 会话优先级/状态（按需） | `updateConversationPriorityById` / `updateConversationStatusById` | conversation |
| 常用回复 FAQ | `getCsFaq(params)` | `GET /cs/faq` |
| 附件上传 | `uploadFile(file)` | file 模块 |

## 七、待联调确认

- `patientId → conversationId` 映射方式：会话对象是否回传患者 id，或需按患者唯一查询会话。
- 消息体真实字段：发送人/发送人类型/消息类型枚举、附件字段、已读字段名与时间格式。
- 消息分页参数名与排序口径；是否需 WebSocket 实时推送，还是轮询拉取。
- FAQ `publishStatus / status` 哪些值算启用；`surgeryType` 不传时是否返回通用问答。
- 客服发送是否走 `sendConversationMessageById`，与患者端 `sendMyConversationMessageById` 的权限边界。

## 八、本段交付清单

1. `CsChatPanel.vue`：会话定位、消息流、输入框、历史/放大弹窗复用。

4. 切换患者清空；空态、加载态、失败兜底；会话映射未确认处不伪造数据。
