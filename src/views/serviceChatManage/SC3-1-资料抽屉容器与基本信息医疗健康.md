# 指令 SC3-1：资料抽屉容器 + 基本信息 / 医疗档案 / 健康管理

> 模块定位：从 SC2 用户信息卡「查看完整资料」打开的只读抽屉，承载患者全量资料。本分段覆盖抽屉骨架与前三个页签；服务关系/沟通记录/附件见 SC3-2。
> **接口口径：cs 模块无患者档案/健康端点，本分段复用 patient 模块只读 GET；客服视角只读，不接写操作（不改档案、不上传/删除附件）。**
> 入参：抽屉打开时传入 `patientId`（雪花 ID 字符串）。空值口径同全局约定。

## 一、技术规范（强制）

- Vue3 `<script setup>` + Element Plus，**不要 TypeScript**；接口从 `../../api/index.js`（API 统一出口，本项目无 `@` 别名），工具从 `@/utils/index.js`。
- 附件 URL 用 `resolveFileUrl` 拼接；相对路径补 baseURL，完整 http(s) 原样返回，空值返回空串。
- 页签懒加载：切到某页签才拉对应端点；抽屉关闭后清空缓存状态。
- 只读视图：不渲染编辑/保存/上传/删除按钮。

## 二、组件结构

```
src/views/serviceChatManage/components/
├── CsProfileDrawer.vue          # 抽屉容器：标题、患者名、六页签 Tab 骨架
└── profile/
    ├── BasicInfoTab.vue         # 基本信息（本分段）
    ├── MedicalRecordTab.vue     # 医疗档案（本分段）
    ├── HealthManageTab.vue       # 健康管理（本分段）
    ├── ServiceRelationTab.vue   # 服务关系（SC3-2）
    ├── CommunicationTab.vue      # 沟通记录（SC3-2）
    └── AttachmentTab.vue         # 附件资料（SC3-2）
```

### 容器职责
- `CsProfileDrawer.vue`：`el-drawer` 右侧滑出；标题「用户完整资料」+ 患者名；维护当前激活 Tab；打开时按 `patientId` 初始化，关闭时重置各页签数据。
- 各页签组件通过 props 接收 `patientId`，内部自行取数。

## 三、基本信息页签（`BasicInfoTab.vue`）

### 数据（聚合优先）

- `getPatientProfileById(id)` → `GET /patients/{id}/profile`：一次性返回 `{ patient, medicalRecord, serviceRelations, tags, sales, attachmentCount }`，本页签优先用它。
- 兜底 `getPatientById(id)` → `GET /patients/{id}`。

### 字段分组映射

| 分组 | 展示字段 | 来源 |
|---|---|---|
| 身份信息 | 姓名 `patient.name`、性别、年龄、出生日期、证件 | `patient`；缺失按空值口径 |
| 联系信息 | 手机号 `patient.phone`、地区/地址 | `patient.region` 等 |
| 服务摘要 | 服务包/购买意向/沟通状态 | `sales`；标签 `tags` 数组 |
| 附件数 | `attachmentCount` | profile 聚合字段 |

- `tags` 字符串数组用 `el-tag` 展示；`sales` 内枚举中文映射沿用全局/模块字典。
- 字段缺失显示 `MISSING_TEXT`；本页签不提供编辑入口。

## 四、医疗档案页签（`MedicalRecordTab.vue`）

### 数据：`getPatientMedicalRecordById(id)` → `GET /patients/{id}/medical-record`

返回 `PatientMedicalRecord`，按设计稿分组展示（字段以 swagger 为准）：

| 分组 | 字段 |
|---|---|
| 就诊信息 | `birthDate`、`bloodPressure`、`bmi`、`allergyHistory` |
| 诊断信息 | `admissionDiagnosis`、`dischargeDiagnosis`、`treatmentProcess`、`chemoPlan` |
| 病史/既往史 | 既往史开关位、相关病史字段 |
| 康复随访 | `rehab*` 康复指导、`followup*` 随访指标 |
| 档案附件 | `attachmentsJson`（`safeParseJson` 解析，URL 经 `resolveFileUrl`） |
| 来源 | `source`：`MANUAL 手动 / OCR 识别` |

- 病历字段较多时分组折叠；长文本保留换行。
- OCR 任务端点（POST/GET OCR）客服不接；本页签只读已落库档案。

## 五、健康管理页签（`HealthManageTab.vue`）

### 数据：`getPatientHealthSummaryById(id, { from, to })` → `GET /patients/{id}/health-summary`

返回 `{ from, to, diet, exercise, weight, bloodPressure, bloodGlucose, sleep, tumorMarkers, bloodRoutine, liverFunction }`；每个模块为 `{ latest, trend }`。

| 卡片模块 | 字段键 | 展示 |
|---|---|---|
| 饮食分析 | `diet` | `latest` 最新记录 + `trend` 趋势 |
| 运动分析 | `exercise` | 同上 |
| 体重动态 | `weight` | 最新值 + 趋势折线 |
| 血糖血压 | `bloodPressure` / `bloodGlucose` | 两指标分栏 |
| 肿瘤标志物 | `tumorMarkers` | 最新值 + 趋势 |
| 血常规 | `bloodRoutine` | 同上 |
| 肝功能/白蛋白 | `liverFunction` | 同上 |

- 时间窗口 `from/to` 默认近 30 天（`YYYY-MM-DD`）；趋势记录子字段名与日期格式待联调确认，先按 `latest/trend` 通用结构渲染。
- 某模块 `latest` 为空对象、`trend` 为空数组时显示该模块空态；不伪造指标值。
- 图表复用工程既有图表组件；无趋势数据时折线留空态。

## 六、本段接口对接（复用 patient，只读 GET）

| 页签 | 函数 | 路径 / 方法 |
|---|---|---|
| 基本信息 | `getPatientProfileById(id)`（兜底 `getPatientById`） | `GET /patients/{id}/profile`（`/patients/{id}`） |
| 医疗档案 | `getPatientMedicalRecordById(id)` | `GET /patients/{id}/medical-record` |
| 健康管理 | `getPatientHealthSummaryById(id, params)` | `GET /patients/{id}/health-summary` |

## 七、待联调确认

- profile `sales`、`serviceRelations` 内嵌对象真实子字段名；基本信息完整字段清单。
- 健康摘要各模块 `latest/trend` 记录项子字段名、单位与日期格式。
- 病历 `attachmentsJson` 结构与档案内附件是否与附件页签去重。
