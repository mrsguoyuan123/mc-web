# 指令 SC1-B：健康数据总览 4 卡与异常数据提醒列表

> 模块定位：工作台顶部「负责用户健康数据总览」区块，含 4 张统计卡 + 异常/关注患者提醒列表。
> **接口口径：cs swagger 无健康总览/提醒列表端点；`getCsStats` 仅回 `highIntent/pendingCall/pendingReply`，不含异常/关注/正常计数与提醒明细。本区块按缺口占位，字段映射先按设计稿预留，禁止写死示例数值与告警。**
> 空值口径同全局约定：缺失（null/undefined/空串）显示红色「接口未提供」，0、false 算有效值。

## 一、技术规范（强制）

- Vue3 `<script setup>` + Element Plus，**不要 TypeScript**；接口从 `../../api/index.js`，工具从 `@/utils/index.js`。
- 雪花 ID 按字符串传；血压/血糖等指标数值为 0 时正常展示，不按缺失处理。
- 区块独立加载、独立容错；加载用骨架，失败显示「加载失败，点击重试」，不影响列表与聊天区。

## 二、组件

```
src/views/serviceChatManage/components/
├── CsHealthOverview.vue     # 健康总览区块容器：标题行 + 4 卡 + 提醒列表
└── CsAlertList.vue          # 异常/关注患者提醒列表（可在容器内组合）
```

### 区块结构（对照设计稿）

- 区块标题：「负责用户健康数据总览」；副标题「仅统计当前客服负责的用户，异常数据可直接进入对应会话跟进。」
- 右上角标签：「负责用户 N 人」（N 为负责用户总数，字段待联调）。
- 4 张统计卡横向排列；下方为「异常数据提醒」折叠列表，标题带「N 位待跟进」标签，可展开/收起。

## 三、4 张统计卡

### 卡片配置（设计稿口径）

| 卡片 | 主数值 | 副文案 | 图标/配色 | 数据来源 |

| 负责用户 | 负责用户总数 | 当前客服服务范围 | 蓝色人像 | 待补端点（见下） |
| 数据异常 | 异常患者数 | 需要优先回访 | 红色告警 | 待补端点 |

## 四、异常数据提醒列表（`CsAlertList.vue`）

### 列表行字段映射（按设计稿预留）

每条提醒对应一名患者，字段预估如下（真实子字段名以联调为准）：

| 行展示 | 预留字段 | 备注 |
|---|---|---|
| 患者姓名 | `patientName` / `name` | 缺失 `MISSING_TEXT` |
| 等级标签 | `level`：`ABNORMAL 异常 / ATTENTION 关注` | 异常红色、关注黄色；与全局健康状态字典对齐 |
| 病情/反馈摘要 | `summary` | 长文本单行折叠，完整内容可换行展示 |
| 血压 | `bloodPressure` | 形如 `136/88 mmHg`；缺失 `-` |
| 血糖 | `bloodGlucose` | 形如 `5.6 mmol/L`；缺失 `-` |
| 用药确认 | `medicationStatusText` | 「今日已确认 / 今日未确认」 |
| 进入会话入口 | `patientId` | 点击 emit `enter-session`，带 `patientId` 跳转/打开对应会话（对接 SC2 会话定位） |

### 列表规则

- 排序：异常优先于关注；同级按提醒时间倒序（时间字段 `alertTime` 待联调）。
- 列表分组样式：异常行浅红底，关注行浅黄底；等级标签置于姓名右侧。
- 「进入会话」文字按钮居右；点击后关闭/保留提醒列表，按 `patientId` 定位会话。
- **缺口占位**：提醒明细随健康总览端点一并补齐；端点未补前列表显示空态「暂无异常数据提醒」，不渲染设计稿中的示例患者（张小美/王芳/赵强/刘洋）。
- 折叠：标题行可展开/收起；收起时只保留标题与「N 位待跟进」标签，不加载明细。

## 五、与其他区块联动

- 点击提醒「进入会话」→ `index.vue` 按 `patientId` 选中患者，联动 SC2 聊天窗/右侧信息卡、SC3 资料抽屉、SC4 电话栏取数。
- 提醒列表的患者应与 `getCsPatientPage` 列表同属当前客服数据范围；越权患者服务端不返回。
- 若后续复用 patient 健康摘要判定异常（`getPatientHealthSummaryById`），需逐患者拉取，性能与口径待评估；不在本版本默认实现。
