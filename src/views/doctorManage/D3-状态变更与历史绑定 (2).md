## 二、变更状态下拉（操作列）

### 下拉项（`doctorStatus` 枚举）

| 选项 | 码值 | 说明 |
|---|---|---|
| 停诊 | `SUSPENDED` | 暂时停诊，保留账号与团队关系 |
| 离职 | `RESIGNED` | 离职，需处理名下患者交接 |
| 注销 | `CANCELLED` | 注销账号，不可恢复 |

> 在职 `ACTIVE` 为当前状态，不作为下拉可选项；已是目标状态的项置灰/隐藏。

### 二次确认
- 点选后弹确认框：标题「确认变更状态」；文案「将 {医生姓名} 的状态变更为 {目标状态}，确认继续吗？」
- 可填变更原因 `reason`（离职/注销建议必填，按后端校验）。
- 离职/注销提示名下患者与团队成员需交接（具体自动转派规则待后端确认）。
- 按钮：「取消」「确认」（红色/主色）。
- 保存：`updateDoctorStatusById(id, { doctorStatus, reason })` → `PUT /doctors/{id}/status`；成功刷新列表，失败消息提示。

### 状态标签
`ACTIVE` 在职绿标签 / `SUSPENDED` 停诊灰橙标签 / `RESIGNED` 离职橙红标签 / `CANCELLED` 注销灰标签 + 置灰行。

## 三、团队与状态变更历史

### 位置
D1 预留的变更历史卡片；空态「暂无变更记录，职称、团队和状态调整会记录在这里。」

### 记录字段（`DoctorChangeLog`）
| 列 | 字段 | 展示 |
|---|---|---|
| 变更时间 | `createTime` | `YYYY-MM-DD HH:mm` |
| 操作人 | `operatorName` | 缺失显示 `-` |
| 变更类型 | `changeType` | `TITLE` 职称 / `TEAM` 团队 / `STATUS` 状态 / `INFO` 信息，中文映射 |
| 变更内容 | `beforeJson` / `afterJson` | 用 `safeParseJson` 解析前后 JSON，拼接前后值描述 |
| 原因 | `reason` | 缺失显示 `-` |

- 接口：`getDoctorChangeLogsById(id, params)` → `GET /doctors/{id}/change-logs`，入参 `changeType / page / pageSize`。
- 按时间倒序；`beforeJson/afterJson` 为 JSON 字符串，解析失败回退原文展示，不抛错。
- 列表页顶部历史卡片默认展示当前选中/首条医生的记录；无选中医生时按全局历史或空态处理（待联调确认是否有全局历史端点）。

### 变更类型映射（放全局 `@/utils/index.js`）

## 四、用户绑定页签

### 4.1 绑定患者列表（患者视角）

> 与「医生列表」平级切换；本页签以**患者**为行，展示其医疗团队里的医生，而非按单个医生展开。

### 数据
- 接口：`getDoctorPatientsById(id, params)` → `GET /doctors/{id}/patients`，分页 `page/pageSize`；若后端提供跨医生的患者团队视图，以实际端点为准（待联调确认）。
- 列表项字段（`DoctorPatientBrief`，按设计稿补全）：`id / name / age / gender / diagnosis(病情) / team(医疗团队数组) / healthStatus`。

### 表格列
| 列 | 字段 | 展示 |
|---|---|---|
| 用户姓名 | `name` | 缺失显示红色「接口未提供」 |
| 年龄 | `age` | 整数；缺失显示 `-` |
| 性别 | `gender` | 男 / 女 |
| 病情 | `diagnosis` | 缺失显示 `-` |

### 医疗团队标签
- `team` 为医生数组，每项 `{ doctorId, name, title, departmentName, hospitalName }`。
- 标签内格式：职称简称 + 姓名，如「张主任(主诊)」「李医生(主治)」「赵医生(住院)」。
- 职称标签配色：主诊深色底白字 / 主治浅灰底 / 住院浅灰底；按 D1 职称枚举映射。
- 团队为空显示 `-`。

### 4.2 调整医患绑定关系弹窗

- 组件：`src/views/doctorManagement/components/PatientTeamDialog.vue`。
- 触发：列表操作列人形图标。
- 标题「调整医患绑定关系」；副标题「为 {患者姓名} 调整医疗团队」；右上角关闭。

#### 当前医疗团队
- 分组标题「当前医疗团队」；逐条列出已绑定医生卡片。
- 卡片内容：职称标签 + 姓名 + 科室 + 医院；右侧「移除」按钮。
- 移除后该医生进入下方「可添加的医生」候选区（前端临时态，点「完成」统一提交）。

#### 可添加的医生
- 分组标题「可添加的医生」；列出尚未绑定的在职医生候选卡片。
- 卡片内容：职称标签 + 姓名 + 科室（+ 医院）；右侧「添加」按钮。
- 候选来源：`getDoctorOptions(params)` → `GET /doctors/options`（在职医生，可按科室/关键字过滤）。

#### 保存
- 底部「完成」（深色主按钮）。
- 提交增量：`addDoctorIds`（新添加）/ `removeDoctorIds`（移除），调 `updateDoctorPatientsById` 对应方向接口；若后端按患者维度维护团队，入参以患者 id + 医生 id 集合为准（待联调确认方向）。
- id 数组由 api 层转字符串；保存成功关闭弹窗、刷新列表；失败消息提示，不清空临时增减。
